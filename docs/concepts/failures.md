# 障害処理

障害は2つの層で扱います。どちらも「状態を捨てて、イベントから作り直す」で回復します（let it crash）。イベントが正なので、メモリ上の状態を捨てても何も失いません。

| 層 | きっかけ | 動作 |
|---|---|---|
| アクター | `handle` / `apply_event` が `StandardError` / `ScriptError` を投げた | そのアクターの状態だけ捨て、呼び出し側に `Rakka::ActorCrashed`。同じシャードの他のアクターは影響を受けない |
| シャード | それ以外の例外でシャード Ractor が異常終了した | Supervisor が再起動（既定で 60秒に3回まで）。返信を待っていた呼び出しは `Rakka::ShardUnavailable`。載っていたアクターは次のコマンドで順次復元 |

これは Akka と同じ構造です。Erlang ではプロセスが VM レベルで実際に終了しますが、Akka は例外を捕まえて状態を捨て、作り直すことで同じ意味論をライブラリで実現しています。Rakka のアクター層も同じです。

{: .note }
`handle` の中の無限ループは、アクター単位では止められません。シャードごと止めるしかない点は Akka と同じ制約です。
