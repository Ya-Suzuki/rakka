落花らっか

Ruby 4.0 · Ractor · Event Sourcing

状態は散っても、
イベントから
何度でも咲く。

Rakka は、Ruby の Ractor の上で数万のアクターを動かす、イベントソーシングのライブラリです。 集約ひとつが花びらひとつ。散っても、幹に残ったイベントから同じ姿で咲き直します。

はじめる 仕組みを読む

gem "rakka", github: "Ya-Suzuki/rakka", glob: "rakka-core/*.gemspec"

四つの性質

  1. 軽

    花びらは軽い

    アクターは Ractor ではなく、シャード Ractor の中の小さな記録です。5万の集約を載せても、Ractor は6つ。1つあたり約1KBです。

    アクターと Ractor
  2. 散

    散っても困らない

    handle が例外を出したら、その花びらだけを散らします。状態はイベントから咲き直すので、何も失いません。

    障害処理
  3. 巡

    風が偏りを均す

    負荷が一つの Ractor に偏ると、溜まった集約を空いた Ractor へ運びます。いつ・どれを運ぶかは実測から決まり、設定はいりません。

    リバランス
  4. 残

    幹は残る

    イベントは書き換えません。楽観ロックで複数のプロセスから書いても整合し、スナップショットで復元は一瞬です。

    永続化と復元

Ruby らしく書く

コマンドを受けてイベントを返す handle と、イベントから状態を作る apply_event。書くのはこの二つだけです。

  • コマンドとイベントは Data.define で、パターンマッチで捌く
  • どちらも純粋な関数なので、DB なしでテストできる
  • 同じ集約へのコマンドは一列に並ぶので、ロックはいらない
