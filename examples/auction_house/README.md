# Auction House — Rakka + Rails のサンプル

ネットオークションを題材にした、Rakka（Ractor + アクター + イベントソーシング）の Rails サンプルです。

オークションを選んだのは、イベントソーシングとアクターの両方が活きるからです。

- **1つの出品に入札が集中する**: 「最高額を読んで、それより高ければ受け付ける」をロックなしで正しく処理する必要がある。1出品 = 1アクターにすると、入札はそのアクターのメールボックスに並んで1件ずつ判断される
- **履歴そのものに価値がある**: 誰がいつ幾らで入札したかは、現在の価格だけを持つ設計では失われる。イベントソーシングならすべて残り、任意の時点の状態も再現できる
- **見せ方の違う読みモデルが複数ある**: 出品一覧、入札者ランキングを、同じイベントからそれぞれ作る

## 動かし方

Ruby 4.0 と PostgreSQL が必要です（リポジトリ直下の `compose.yaml` で起動できます）。

```bash
docker compose up -d          # リポジトリ直下で
cd examples/auction_house
bundle install
bin/rails db:setup            # DB作成 + マイグレーション + サンプルデータ
bin/rails server
```

http://localhost:3000 を開き、右上の「あなた」で名前を切り替えながら出品・入札できます。

## 見どころ

### 1. 1出品 = 1アクター（`app/aggregates/auction.rb`）

コマンド（出品・入札・終了）を受け取り、ルールに照らしてイベントを返す `handle` と、イベントから状態を作る `apply_event` だけでできています。どちらも純粋関数なので、DBもアクターも使わずにテストできます（`test/aggregates/auction_test.rb`）。

即決価格以上の入札は、`BidPlaced` と `Closed` の2つのイベントを1回で書きます。

### 2. 同時入札でも取りこぼさない

```bash
bin/rails auction:bidding_war     # 20人 × 10回、同じ出品に同時に入札
```

```
入札 200件（1670件/秒）
  受理: 36件
  拒否: 164件（最低入札額に届いていません）

確認
  受理した入札 = 記録された入札イベント: OK
  入札額は常に前の最高額 + 100円以上: OK
  現在価格 = 受理した最高額（6300円）: OK
```

各スレッドは「今の価格を見て、それより高い額で入札」しますが、見てから届くまでの間に他の人の入札が先に処理されます。アクターが1件ずつ判断するので、古い価格を見て出した入札は正しく拒否され、受理された入札額は必ず単調に増えます。アプリ側にロックはありません。

### 3. イベント履歴とタイムトラベル（出品の詳細画面）

右側にその出品のイベントがすべて並びます。行をクリックすると、その時点の状態を表示します。過去の状態はどこにも保存しておらず、イベントを `apply_event` で順に適用し直して作っています（`Auction.history`）。

### 4. 読みモデル（`app/projections/`）

一覧とランキングは、書き込みとは別のテーブル（`auction_listings` / `bids`）から表示しています。イベントを購読して更新します（`config/initializers/rakka.rb`）。

`Projections.apply` は、ストリームごとに反映済みのversionを `stream_checkpoints` に持ち、読みモデルと同じトランザクションで更新します。そのため次の性質があります。

- 同じイベントが2回届いても、2回は反映しない
- 途中のイベントが届かなかったら（発行前にプロセスが落ちた等）、次のイベントが届いた時点でイベントストアから読んで埋める
- 複数のプロセスが同じ出品のイベントを発行しても、行ロックで順に反映される

### 5. 読みモデルは捨てて作り直せる

```bash
bin/rails projections:rebuild
```

読みモデルをすべて消し、イベントストアの全イベントから作り直します。集計方法を変えたときや、新しい読みモデルを足したときも、これで過去の分が埋まります。

### 6. 書き込み側と読み込み側のずれ

詳細画面の現在の状態は、アクターに直接聞いた最新のものです。一覧は読みモデルなので、わずかに遅れて反映されます。詳細画面の下に、読みモデルがどのversionまで反映済みかを表示しています。

## テスト

```bash
bin/rails test
```

| ファイル | 内容 |
|---|---|
| `test/aggregates/auction_test.rb` | 過去のイベント + コマンド → 新しいイベント、の形で書いたルールのテスト |
| `test/aggregates/concurrent_bidding_test.rb` | 同時入札で取りこぼしがないこと |
| `test/projections/projections_test.rb` | 読みモデルの反映、重複・欠落への強さ、作り直し |
| `test/integration/auction_flow_test.rb` | 画面からの出品・入札・終了、タイムトラベル表示 |

## Rails で使うときの注意（このサンプルで分かったこと）

- `handle` / `apply_event` はシャードRactorの中で動くので、ActiveRecord やグローバルな状態には触れない。使えるのは引数だけ
- イベントの購読ハンドラは Rakka のスレッドで動く。rakka-rails が Rails の executor で包んで呼ぶ
- リクエストやテストの中で読みモデルの反映を待つときは、クエリキャッシュに注意する（同じSQLの結果がキャッシュされ、いつまでも変わらないように見える）。`Projections.caught_up?` は `uncached` で数えている
